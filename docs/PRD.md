## 1. 목표와 성공 기준

**목표: 「이 노트를 매주 다시 열어보는가」를 가장 싸게 확인한다.**

성공·실패 기준은 시험 **시작 전에** 아래로 못박고 바꾸지 않는다 ([concept.md](concept.md) §9).

| | 기준 | 재는 법 |
|---|---|---|
| **계속** | 6주째에 시험 사용자 **절반 넘게(11명+)** 그 주에 노트를 1번 이상 열었다 **그리고** **5명 이상** 「돈 내고도 보겠다」 | `views` 주별 고유 사용자 수 · 6주째 설문 |
| **접음** | 3주째 재방문 **30% 미만(6명 미만)** | `views` |
| 그 사이 | 계속도 접음도 아니면 — 6주 끝에 데이터를 보고 한 번만 정한다. 기준을 고치지 않는다 | |

「다시 열었다」 = 그 주(월~일)에 자기 종목 노트 페이지를 1번 이상 연 것.

## 4. 노트 규칙 (F4 상세)

1. **숫자는 한장 코드가 계산한다.** AI 에게 숫자를 묻지 않는다.
2. **AI 는 두 가지만 한다.** ① **읽기** — 공시·사업보고서를 읽어 분류·호재/악재·리스크 태그로 바꾼다. ② **쓰기** — 코드가 계산한 숫자와 사실(「사실 묶음」)을 받아 이어지는 쉬운 글로 쓴다.
2-1. **빈칸 채우기 (2026-10-07).** AI 는 숫자·연도·날짜·늘었다/줄었다를 직접 쓰지 않고 `{F1.값}` `{F1.방향}` 같은 빈칸만 쓴다 — 코드가 채운다. 빈칸 밖에 숫자가 하나라도 있거나 사실과 반대 방향 낱말을 쓰면 글째 버린다. 응답은 OpenAI 구조화 출력(strict)으로 받아 근거 id 를 이 노트의 사실 id 로만 고르게 한다.
3. **숫자 대조 검사.** AI 가 쓴 글의 숫자는 전부 사실 묶음에 있는 값이어야 한다. 하나라도 없는 숫자가 있거나 금지어(아래 8)가 있으면 **그 글을 버리고 코드가 조립한 문장**(퀀트점프 문장 조립 코드에서 출발)으로 대신 싣는다. 버린 횟수는 기록한다.
4. **모든 문장에 링크.** 공시·재무 → DART 원문. 뉴스 → 언론사 원문. 계산값(가격·민감도·밸류) → 「계산 방법」 공개 페이지의 해당 항목.
5. **용어 풀이는 한장이 가진 고정 사전**(용어 → 한 줄)에서 붙인다. 노트에서 처음 나올 때만.
6. 민감도 문장 뒤에는 항상 「과거에 그랬다는 측정이지, 앞으로도 그렇다는 보장은 없어요.」
7. 노트 맨 아래 고정 문구: 「사라·팔아라는 의견도, 목표주가도, 앞으로의 예측도 없어요.」
8. **금지어**: `매수·매도·비중·목표주가·예측·전망(한장 말로)·오를 것·내릴 것` — 검사 3에서 걸러진다. 기사가 한 전망은 「기사는 ~라고 써요」로만.
9. **이어지는 글.** 숫자를 하나씩 나열하지 않는다. 절마다 한 흐름(예: 1년 → 석 달 → 한 달 · 번 것 → 살림 → 돌려준 것 → 가격)으로, 다른 절의 숫자와 이어 「그래서 이 회사에 무슨 뜻인가」까지 간다. 맨 앞에 「한 장 요약」 세 문장. 모양은 [sample-note.md](sample-note.md).
10. **뉴스는 짧은 글 + 기사 목록.** 이번 주 이야기 하나로 묶는다. **기사 제목만** 보고 쓴다(본문은 가져오지 않는다 — 불변식 3). 끝에 「한장의 예측이 아니에요」.

### 5.1 재료 — 쓸 권리가 확인된 것만 ([data-rights.md](data-rights.md), 2026-10-07 약관 원문 확인)

**주가는 무료로 쓸 길이 없다.** 1단계 노트는 재무·공시·사업보고서·일정으로 쓰고, 가격·PER·PBR·민감도·차트는 시세를 산 뒤에 붙인다.

| 재료 | 출처 | 1단계 | 확인할 것 |
|---|---|---|---|
| 공시 · 재무 · 사업보고서 · 일정 | **DART** (OpenDART API) | ✅ | 서비스용은 기업용 키 |
| 환율 · 국고채 3년 | **한국은행 ECOS** | ✅ (주가를 사야 민감도에 쓸 수 있다) | 출처 「한국은행 ECOS」 표시 · 지표별 작성기관 |
| 일별 종가 · 시가총액 | **한국거래소 유료 데이터** (견적 문의) | ❌ 사기 전까지 없음 | 공공데이터포털·KRX OPEN API 는 상업 금지 · 제3자 제공 금지 |
| 뉴스 | 구글 뉴스 RSS (퀀트점프와 같은 수집) | ⚠️ **개발 중 나 혼자 볼 때만** | 구글 약관상 개인용만 — **남에게 보이기 전(20명 시험 전)에 바꾼다**: 사람이 읽고 메모 → AI 문장, 또는 빅카인즈·통신사 계약. 결정은 서비스화 때로 미룸 (2026-10-07) |

### 5.2 매일 도는 순서 (아침 7시 — `python -m hanjang.daily`, 노트의 주 = 그 월요일. 화면의 「업데이트: 매일 07:00 (바뀐 종목만)」과 같게)

월요일은 그 주 노트를 전부 새로 쓰고 ⑦ 안내 메일을 보낸다. 화~일은 ①~④ 를 똑같이 하고, **이번 주 노트의 사실과 달라진 종목만** ⑤⑥ 을 다시 한다 —
재무·공시·지분 보고가 바뀌면 누구 종목이든, 기사가 바뀌면 누군가 담은 종목만. 다시 쓴 노트는 화면에 「· 10월 8일 고침」.

```
① 받기      DART 공시·재무 · 시세 · 거시 — 지난주 것만 더 받는다 (멱등: 다시 돌려도 중복 없음)
② 계산      수정주가 보정 → 수익률·52주 위치 · 재무 증감·PER·PBR·부채비율·ROE · 밸류 백분위 · 민감도(250거래일 회귀, 지표 전부)
③ 읽기 (AI) 새 공시·사업보고서만 — 분류·호재/악재·강도·리스크 태그. 이미 읽은 건 다시 안 읽는다
④ 사실 묶음  종목마다 ②③ 결과 + 링크를 하나의 JSON 으로
⑤ 쓰기 (AI) 사실 묶음 → 노트 글 (§4) → 숫자 대조 검사 → 통과 못 하면 코드 문장으로
⑥ 저장      notes 에 (종목, 주) 한 장
⑦ 안내      담은 종목에 이번 주 노트가 있는 사용자에게만 메일 한 통 (단계가 실패하면 보내지 않는다)
```

**퀀트점프에서 복사해 올 코드**: DART 받기·재무 계산(①②) · 수정주가 보정 · 민감도 회귀(②) · 공시 reader 프롬프트(③) · 노트 문장 조립(⑤의 대체 문장). 복사한 파일 첫 줄에 「퀀트점프 어디서 왔는지」를 적는다.
**복사하지 않는 것**: 비중 · 예측 · 백테스트 · 엔진 장부 · 토스 수급 · 야후파이낸스.

### 5.3 비용 감

100종목 × 주 1회. **첫 실행 실측 (2026-10-07)**: 공시 1,512건 제목 읽기(gpt-4.1-mini) + 노트 100장 쓰기(gpt-4.1) = **$1.08** (읽기 첫 회 포함). 매주는 새 공시만 읽으니 **주 약 $1 · 월 약 6천 원**. 노트 100장 중 95장이 AI 글로 검사를 통과, 5장은 코드 문장으로 대체.

**글쓰기 모델 비교 (2026-10-08, 같은 사실 12종목)**: gpt-4.1 $0.199 · 12콜 / gpt-4.1-mini $0.054 · 18콜(다시 쓰기 6번). 둘 다 12장 검사 통과.
mini 는 ① 절 하나를 통째로 빠뜨리고(삼성전자 「요즘 무슨 일」) ② 「매출이 줄었어 122.7조원이었고」 같은 어색한 문장 ③ 기사의 주가 전망을 옮김 → **글쓰기는 gpt-4.1 유지**, 비용은 「바뀐 종목만 다시 쓰기」로 줄인다.
매일 실행 비용 = 월요일 전체(약 $1.6) + 화~일 바뀐 종목만 — 실측은 [plan.md](plan.md) 기록.

## 7. 기술 — 가장 단순한 것

| 영역 | 고른 것 | 이유 · 바꿀 조건 |
|---|---|---|
| 언어 | 파이썬 하나 | 복사해 올 퀀트점프 코드가 파이썬 |
| 서버·화면 | 서버에서 HTML 그리기 | 사용자 20명이라 프론트 프레임워크 불필요. 앱 단계(4)에서 재검토 |
